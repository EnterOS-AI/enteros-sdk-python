# tools/ — contracts codegen + validation (ONE home, TWO IDL kinds)

`molecule-ai-sdk` is the consolidated home for the MoleculesAI contract SSOT.
`tools/` holds the codegen + validation pipeline over a single `contracts/` dir
that carries **two** IDL conventions, each generated by the SAME three scripts:

```
contracts/cloudproviders.yaml                     ─┐  (flat YAML SSOT, #40)
contracts/<domain>/<name>.contract.json           ─┤  (JSON-Schema draft 2020-12
   validated against <name>.schema.json            │   instances — folded from
   domains: mcp, plugin-manifest, workspace-template,│  molecule-contracts)
   org-template, catalog, provision-request,        │
   promote-request, workspace-comms                ─┘
        │
        ▼  node tools/gen-<lang>.mjs   (each dispatches over BOTH kinds)
gen/go/cloudprovider/…        gen/go/molcontracts/…      ─┐ generated typed
gen/ts/cloudproviders.generated.ts  gen/ts/{contract,workspace_comms,catalog}_gen.ts │ bindings — NEVER
gen/python/cloudproviders.py  gen/python/{contract,workspace_comms,catalog}_gen.py   ─┘ hand-edited
```

## The two IDL kinds

1. **cloud-provider YAML** — `contracts/cloudproviders.yaml`. The generators
   derive the provider catalog (Go `cloudprovider` package, TS
   `cloudproviders.generated.ts`, Python `cloudproviders.py`) from it via
   `lib/cloudproviders.mjs`. Semantic invariants (unique ids, one `is_local`,
   `{persist} ∪ {""}` == migration-056) are asserted by
   `tests/test_cloudproviders_contract.py`.

2. **JSON-Schema contracts** — folded verbatim from `molecule-contracts`. Each
   `contracts/<domain>/<name>.contract.json` is the canonical instance; the
   sibling `<name>.schema.json` pins its shape + `const`/`enum` invariants (e.g.
   `required_tool` == `"provision_workspace"`). The generators emit, into
   `gen/go/molcontracts` (`package molcontracts`) + `gen/ts` + `gen/python`
   (package `molecule_ai_contracts`):
   - `contract_gen.*` — the mcp plugin-delivery scalars + full `Contract` value
     (derived from the `mcp/` **instance**),
   - `provision_request_gen.go` — the core→control-plane provision endpoint,
     ordered field names, and per-field consume metadata (derived from the
     `provision-request/` **instance**),
   - `schema_assets_gen.go` — raw schema JSON assets that Go consumers need to
     compile directly (currently `plugin-manifest.schema.json`),
   - `workspace_comms_gen.*` — the register/heartbeat/a2a/agent-card message
     models (derived from the `workspace-comms/` **schemas** via
     `lib/comms-schema.mjs`),
   - `catalog_gen.*` — the plugin-manifest/workspace-template/org-template
     manifests + the unified catalog-entry envelope (derived from those schemas).

Every generated value is **derived** — no contract value is hardcoded in a
generator. All three generators are Node `.mjs` scripts, so regeneration and the
CI drift gate need only `node` — no Go/Python/TS toolchain.

## `gen/` is NEVER hand-edited

To regenerate after a contract change:

```sh
node tools/gen-go.mjs        # cloudprovider + gen/go/molcontracts/*
node tools/gen-ts.mjs        # cloudproviders.generated.ts + gen/ts/{contract,workspace_comms,catalog}_gen.ts
node tools/gen-python.mjs    # cloudproviders.py + gen/python/{contract,workspace_comms,catalog}_gen.py
```

The hand-authored, NON-generated files that also live under `gen/` — the
`gen/go/{llmwire,tools,doc.go,deps_test.go,go.mod,go.sum}` +
`cloudprovider_test.go`, `gen/go/molcontracts/*_test.go`, the TS package shim
`gen/ts/{index.ts,package.json,tsconfig.json}`, and the Python package shim
`gen/python/{__init__.py,pyproject.toml}` — are outside the generators' write
paths, so a fresh regen never clobbers them.

## CI gate (`.gitea/workflows/contracts-codegen-drift.yml`)

One merged fail-closed gate over the whole `contracts/` SSOT (supersedes the
cloudprovider-only gate), with a strict `all-required` aggregator:

| Job | What it does |
| --- | --- |
| `validate` | `check-jsonschema` every `contracts/*/*.contract.json` against its sibling `*.schema.json` (makes the `const`/`enum`/`required` pins load-bearing). |
| `codegen-drift` | re-run ALL generators (both IDL kinds) then `git diff --exit-code` over the generated paths. Fails on any drift. |
| `contract-conformance` | jsonschema-validate `cloudproviders.yaml` + assert its semantic invariants. |
| `go-parity` | `go build/vet/test ./...` in `gen/go` incl. the folded `molcontracts` package + the cloudprovider behavior oracle + `nodup-lint` + the SDK dependency guard. |

## Published dists (kept byte-stable)

The folded bindings publish under their historical dist names so consumers need
no source change — distinct from `molecule-ai-sdk`'s own JS/Py surface:

- TS: `@molecule-ai/contracts` (`gen/ts/package.json`), subpaths `./contract` +
  `./workspace-comms`.
- Python: `molecule-ai-contracts` / import name `molecule_ai_contracts`
  (`gen/python/pyproject.toml`).
- Go: `go.moleculesai.app/sdk/gen/go/molcontracts` (the folded package, additive
  to the single `go.moleculesai.app/sdk/gen/go` module — a subdir module of the
  molecule-ai-sdk repo; the /sdk vanity prefix binds to the repo root).

## Registry SSOT (`contracts/registry.yaml`) — the ONE container-registry source

`contracts/registry.yaml` is the single source of truth for the **container
image registry** every MoleculesAI image reference derives from (host/owner,
box auth SHAPE, retention policy, optional dynamic pull-through mirror). It is
the container analogue of `cloudproviders.yaml`. It has its OWN self-contained
generator + drift gate, decoupled from the cloudprovider/molcontracts pipeline:

```
contracts/registry.yaml            (flat YAML SSOT + contracts/registry.schema.json)
        │  node tools/gen-registry.mjs
        ▼
gen/registry/registry.env          (source-able fragment for CI / compose / scripts)
gen/go/registry/registry.go        (package registry — Go consts CP + core re-export)
```

Gate: `.gitea/workflows/registry-ssot-drift.yml` (`drift` re-runs the generator
and `git diff --exit-code`s `gen/`; `conformance` runs
`tests/test_registry_contract.py` — schema-validates the YAML and asserts the
load-bearing invariant `prefix == host/owner` plus "both derivation seams carry
the same prefix"). `gen/` is NEVER hand-edited.

### Switching registries (ECR ↔ GHCR ↔ our own) — ONE value, three seams

All three seams default to `registry.prefix`; override ANY ONE to switch with no
code edit:

| Seam | Where | How to switch |
| --- | --- | --- |
| Runtime (Go) | CP + core `RegistryPrefix()` read env `MOLECULE_IMAGE_REGISTRY` | set the env at deploy (Railway / compose / EC2 user-data) |
| CI publish | publisher `IMAGE_NAME: ${{ vars.MOLECULE_REGISTRY \|\| '<prefix>' }}/…` | set org/repo Actions var `MOLECULE_REGISTRY` |
| Baked default | `registry.prefix` in this file | edit `prefix`, `node tools/gen-registry.mjs`, commit |

`switch_examples:` in the YAML lists the canonical prefixes for our registry,
ECR prod (153263036946), ECR staging (004947743811), and GHCR.

### Dynamic pull-through mirror (off by default)

`mirror.enabled: true` + an `upstreams:` list turns our registry into an
on-demand proxy-cache of an upstream (the container analogue of the
source-provider ecosystem) — no explicit mirror-push. Declared here so enabling
it is a config edit, not a code change.

### Retention

`retention:` declares the keep-N-per-package policy the operator prune enforces
(`operator-config/ops/registry-retention-prune.sh`): keep at most
`keep_max_versions` (5) versions per container package, never prune a
`keep_tags` head (latest / staging-latest / staging) or a **pinned** digest
(`runtime_image_pins`), always prune untagged. The dormant ECR side keeps its
own AWS-native lifecycle (`scripts/ops/ensure-ecr-lifecycle.sh`, keep-10).
